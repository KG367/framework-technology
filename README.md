# Система планирования приготовления блюд

Консольное приложение для планирования домашнего питания.

## Назначение

Приложение позволяет:

- просматривать каталог блюд с ингредиентами;
- искать блюда по названию;
- подбирать блюда по приёму пищи и времени готовки;
- планировать приёмы пищи на даты;
- удалять приёмы пищи из плана;
- строить список покупок из плана;
- подсчитывать калорийность;
- вести профиль пользователя (цель по калориям, бюджет);
- управлять ограничениями питания (аллергии, диеты);
- сохранять все данные в JSON-файлах.

## Предметная область

Домашнее питание: планирование меню, закупка ингредиентов и учёт
ограничений в питании.

## Модель предметной области

### Ingredient — ингредиент блюда

Объект `Ingredient` описывает один ингредиент с количеством.

**Атрибуты:**

- `name` — название ингредиента;
- `amount` — количество (например, «3 шт», «50 г»).

**Методы:**

- `__str__()` — строковое представление (`яйца: 3 шт`);
- `from_data()` — создание из словаря (JSON);
- `to_data()` — преобразование в словарь для сохранения.

### Dish — блюдо

Объект `Dish` описывает готовое блюдо и хранит ссылки
на объекты `Ingredient`.

**Атрибуты:**

- `name` — название блюда;
- `slot` — приём пищи (`завтрак`, `обед`, `ужин`, `перекус`);
- `minutes` — время готовки (мин);
- `kcal` — калорийность одной порции;
- `ingredients: List[Ingredient]` — состав блюда.

**Методы:**

- `__str__()` — строковое представление;
- `is_allowed(restrictions)` — проверка, что блюдо не содержит
  запрещённых ингредиентов;
- `from_data()` — создание из словаря (JSON);
- `to_data()` — преобразование в словарь.

### Meal — приём пищи

Объект `Meal` связывает три сущности: дату/слот, блюдо и пользователя, для которого этот приём пищи запланирован.

**Атрибуты:**

- `date` — ISO-дата (`YYYY-MM-DD`);
- `slot` — приём пищи;
- `dish: Dish` — объект блюда (не название);
- `user: UserProfile` — объект пользователя, которому принадлежит приём пищи;
- `portions` — число порций.

**Методы:**

- `__str__()` — строковое представление;
- `from_data(data, dishes, user)` — создание из словаря с поиском блюда в каталоге и связыванием с указанным пользователем;
  (возвращает `None`, если блюдо не найдено);
- `to_data()` — преобразование в словарь (ссылка на блюдо и пользователя сохраняются по имени).
### UserProfile — профиль пользователя

Объект `UserProfile` описывает пользователя и его ограничения.

**Атрибуты:**

- `name` — имя;
- `target_kcal` — цель по калориям (ккал/день);
- `budget` — недельный бюджет (руб);
- `restrictions: List[str]` — ограничения питания.

**Методы:**

- `__str__()` — строковое представление;
- `set_name(name)` / `set_target_kcal(target)` / `set_budget(budget)`;
- `add_restriction(ingredient)` / `remove_restriction(ingredient)`;
- `is_dish_allowed(dish)` — проверка блюда на совместимость;
- `filter_dishes(dishes)` — фильтр каталога;
- `from_data()` / `to_data()` — преобразование JSON.

## Функции обработки коллекций

Функции обработки коллекций объектов остаются обычными функциями
(не методами), поскольку их задача — работа с набором, а не с одним
объектом.

| Функция | Модуль | Назначение |
|---|---|---|
| `find_by_name` | `models/dish.py` | поиск блюда по подстроке названия |
| `filter_dishes` | `models/dish.py` | фильтр по слоту и времени |
| `find_meal` | `models/meal.py` | поиск приёма пищи по дате и слоту |
| `add_meal` | `models/meal.py` | добавление приёма пищи пользователю |
| `remove_meal` | `models/meal.py` | удаление приёма пищи |
| `total_calories` | `models/meal.py` | суммарная калорийность плана |
| `build_shopping_list` | `models/meal.py` | агрегированный список покупок |

## Взаимодействие объектов

```

UserProfile  ──фильтрует──▶  Dish
│
│ ingredients
▼
Ingredient

Meal  ──ссылается на──▶  Dish

```

- `Meal` хранит ссылку на объект `Dish` (не на название);
- `UserProfile` работает с `Dish` через метод `is_dish_allowed()`;
- `Dish` содержит список объектов `Ingredient`.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

- `data/dishes.json` — каталог блюд;
- `data/plan.json` — сохранённый план питания;
- `data/user.json` — профиль пользователя.

При загрузке JSON преобразуется в объекты `Dish`, `Meal`,
`UserProfile`. При сохранении объекты преобразуются обратно в JSON.
Преобразование выполняет модуль `storage.py`, а не `main.py`.

При сохранении приёма пищи ссылки на блюдо и пользователя
сохраняются как имена; при загрузке блюдо ищется в каталоге,
а пользователь передаётся в `load_plan()` явно — в проекте один
профиль.

## Назначение модулей

- `main.py` — точка входа: меню, пользовательские сценарии.
  Не хранит данные предметной области и не дублирует логику
  моделей.
- `storage.py` — преобразование JSON ↔ объекты.
- `utils.py` — даты (`parse_date`, `format_date`) и ввод (`ask_int`).
- `models/` — классы предметной области и функции обработки
  коллекций объектов.

## Требования

- Python 3.9+;
- Основной код использует **только стандартную библиотеку**.
- Для тестов и проверки качества: `pytest`, `flake8`, `mypy`.
